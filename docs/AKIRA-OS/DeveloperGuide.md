# Developer Guide for AKIRA OS

## Overview
This guide provides contributors with the essential information to develop, test, and maintain the AKIRA OS codebase. It consolidates repository conventions, tooling, coding standards, and migration steps introduced during the recent modernization sprint.

## Repository Structure
- `src/` – Core library code. **No `process.exit` calls are allowed here**; termination logic must be confined to CLI entry points.
- `scripts/` – Build, validation, and migration scripts. CLI utilities live under `scripts/` and may invoke `process.exit`.
- `bin/` – Executable wrappers for CLI tools (e.g., `validate_migration.ts`).
- `tests/` – Vitest test suite.
- `docs/` – Documentation, including this Developer Guide.

## Tooling
- **Node.js** (v18+ recommended)
- **npm** for package management
- **Vitest** for testing (`npm run test`)
- **ESLint** (configured in `eslint.config.js`)
- **Prettier** for formatting

## Coding Standards
- Follow the existing architecture and folder layout.
- Keep changes minimal and modular.
- Write TypeScript with strict typing (`noImplicitAny`, `strictNullChecks`).
- Reuse existing components and services.
- Do not introduce new dependencies unless absolutely required.

## ESLint Rules
- The repository enforces a custom rule that prohibits `process.exit` in any file under `src/`.
- This rule is defined in `eslint.config.js` via a `no-restricted-properties` override targeting `src/**/*.ts`, `src/**/*.tsx`, `src/**/*.js`, and `src/**/*.jsx`.
- CLI entry points in `scripts/` and `bin/` may use `process.exit` as needed.

## Test Suite Migration
- Legacy test runner (`runAll`) and `process.exit` usage have been removed.
- Tests now run natively with Vitest. Use `npm run test` to execute the full suite.
- Ensure new tests follow Vitest conventions and live under `tests/`.

## CLI Entry‑Point Guidelines
- Keep CLI utilities thin wrappers that import pure library functions.
- Example: `src/persistence/validate_migration.ts` now delegates to `src/persistence/validateMigration.ts`.
- CLI files may reside in `scripts/` or `bin/` and may call `process.exit` for explicit termination.

## Updating Documentation
- When API contracts, architecture, or CLI behavior changes, update the relevant sections in this guide and the corresponding module docs under `docs/`.
